# 2026-08-31 工作日志

## 修复：新增素材在页面不显示（Docker 部署根因）
- 现象：用户硬刷 https://127.0.0.1:7000 后仍看不到 version-7 的学历段/考试段内容。
- 排查：netstat 显示 7000 监听者是 `com.docker.backend.exe`(5168) 与 `wslrelay.exe`(30500)，并非裸 node —— 应用跑在 Docker 容器 `english-reading`(镜像 am-english-reader:1.0.0)。curl 容器返回的 materials.json 是 version 1，而宿主机 E:\Desktop\English_Reading\public\data\materials.json 已 version 7（1402 条）。Dockerfile 把 public/ 在 build 时 COPY 进镜像，宿主机改动不进容器。
- 解法：docker-compose.yml 将 `./public` 与 `./server` 改为绑定挂载；`docker compose up -d` 重建容器。验证：容器 healthy、返回 version 7、1402 条、Cache-Control: no-cache（http.js 缓存修复同步生效）。
- 教训：离线环境 `docker compose build` 会因 Docker 需联网查 node:22-slim 清单而失败；离线迭代只能靠绑定挂载 + `docker restart`，不能重建镜像。
- 后续：用户浏览器 Ctrl+Shift+R 即可看到全部 10 level / 250 组 / 1402 条。

## 修复：用户自己加的 15 个（实为 16 个）自定义素材"消失"
- 现象：用户反馈自己添加的 15 个素材不见了。
- 根因：自定义素材走 UI 存进 `data/app.db` 的 `custom_texts` 表。用户当初是用 `npm start` **裸跑**加的，数据在宿主机 `E:\Desktop\English_Reading\data/app.db`（16 条）；而 Docker 容器读的是命名卷 `er_data`（容器内 /app/data），两者**不互通**，容器里 custom_texts=0。
- 恢复（已验证）：从宿主机 app.db 导出 16 条 custom_texts → 停容器 → 用应用镜像起临时容器 `docker run --rm -v english_reading_er_data:/data -v <scripts>:/scripts am-english-reader:1.0.0 node --experimental-sqlite /scripts/_insert.mjs` 写入卷内 app.db → 重启容器。API `GET /api/progress` 现返回 customTexts=16（含"工程英语""第1~15段旁白"）。
- 注意：离线时 `docker run node:22-slim` 拉不到基础镜像（本地无缓存），必须用已存在的 `am-english-reader:1.0.0` 镜像。临时脚本已清理。
- 结论：用户现统一走 Docker，自定义素材落 `er_data` 卷；宿主机 ./data 是裸跑遗留，别再混用。
